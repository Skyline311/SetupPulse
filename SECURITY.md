# Security reports

SetupPulse is an early preview. Fixes are developed against the latest source and preview version; there is no long-term maintenance commitment for older builds.

For a suspected security vulnerability, use **Security → Report a vulnerability** on the GitHub repository when private vulnerability reporting is enabled. Do not post exploit details, credentials, or unredacted local diagnostics in a public issue.

If private reporting is not available, open an issue asking the maintainer for a private reporting channel, without including vulnerability details. The repository owner must enable private reporting when the public repository is created; no dedicated email address is configured yet.

Useful details include the affected version, a minimal reproduction, impact, and whether the issue concerns the native Windows host, WebView2 bridge, profile import, or dependencies. There is no guaranteed response time.

Ordinary crashes, compatibility problems, and feature requests belong in the normal issue templates.
